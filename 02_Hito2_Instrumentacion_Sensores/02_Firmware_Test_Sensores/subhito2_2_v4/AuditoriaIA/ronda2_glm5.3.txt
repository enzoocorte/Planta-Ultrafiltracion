🔍 A. Escenarios de borde del conteo recíproco — 3 hallazgos (1 real, 2 documentales)
A.1 🔴 El wrap del período tras parada larga (hardening recomendado)
uint32_t micros() envuelve cada ~71.6 min. Si la bomba estuvo detenida más de 71 min, el primer flanco del reinicio calcula dt = t - _t_ultimo sobre el contador envuelto → puede dar un valor pequeño falso (ej. 10 ms) → _periodo_us=10000 → ventana siguiente n==1 → _f = 100 Hz fantasma. Probabilidad baja, pero un ensayo que arranca después del almuerzo puede caer justo ahí. Guard en la ISR:

cpp

void IRAM_ATTR Caudalimetro::isrPuente(void* arg) {
  Caudalimetro* c = reinterpret_cast<Caudalimetro*>(arg);
  uint32_t t = micros();
  uint32_t dt = t - c->_t_ultimo;
  if (dt > 10000000UL) {                       // hueco > 10 s: parada larga o wrap
    portENTER_CRITICAL_ISR(&c->_mux);
    c->_t_primero = t;  c->_periodo_us = 0;    // re-armar sin período falso
    c->_t_ultimo  = t;  c->_pulsos++;          // el pulso cuenta volumen, no frecuencia
    portEXIT_CRITICAL_ISR(&c->_mux);
    return;
  }
  if (dt >= FILTRO_RUIDO_US) { /* ... igual que ahora ... */ }
}
A.2 La retención suprime temporalmente el "SIN SEÑAL" (documentar, no corregir)
Durante la retención, _f > 0.1f resetea _segSinPulso → la alerta de falla se retrasa en 2.5 × período + 5 s. Números: a 5.5 Hz → +0.46 s (imperceptible); a 1 Hz → 7.5 s; a 0.2 Hz → ~17.5 s. Siempre finito y acotado — aceptable, pero anotarlo en el manual para que nadie lo confunda con un fallo de detección.

A.3 Menores
setRPM usa std::isfinite → falta #include <cmath> en Bomba.h.
El frenado de inversión usa DESACEL_AJUSTE (8 RPM/s): desde 100 RPM son ~12.5 s de frenado. Válido, pero si el retrolavado frecuente lo hace lento, un _invirtiendo ? 20 : DESACEL_AJUSTE lo lleva a ~5 s. Decisión de proceso, no bug.
A.4 ⚠️ Pendiente científico que arrastro de Ronda 1: procedencia de K_ALIM=154.62 y K_PERM=55
Ninguna de las dos calibraciones cierra contra el nominal (98) con la dispersión normal de turbinas (±10%). Dos hipótesis físicas que explicarían el +58% del feed y que conviene verificar/citar:

Orientación de montaje: la K de datasheet asume horizontal. El FEED está montado vertical ascendente (fricción axial del eje sobre la turbina) → K aparente mayor. Test: calibrar por probeta en la orientación instalada (ya lo hacen — solo falta documentar que la K es de instalación, no de datasheet).
K_PERM=55 calibrado a 100 mL/min, debajo del mínimo de spec (300 mL/min): en zona sub-espec la turbina resbala → K aparente menor. El comentario "régimen laminar" no explica un salto de 2.8× entre unidades.
Y la pregunta incómoda que el jurado hará: ¿los 680 mL/min de ML=13.6 salieron de probeta o del propio caudalímetro? Si fue del sensor, ML y K están calibrados circularmente (se auto-validan). Regla de oro para el protocolo: ML solo contra probeta/balanza; K solo contra probeta; nunca uno contra el otro.

Sincronización: seqlock (ni doble-buffer con punteros ni mutex)
Con un POD de ~100 B y un lector a 2 Hz contra un escritor a 20 Hz, la contención es irrelevante en magnitud — pero el seqlock da lo mejor de ambos mundos: escritura sin bloqueo jamás (el control nunca espera) y lectura sin bloqueo con reintento. Cero inversión de prioridad por diseño:

cpp

struct EstadoPlanta { float rpm, rpmObj, qAlim, qPerm, qRet, recov, volA, volP, tmpBar, mlRev; bool cruce; };
EstadoPlanta g_estado;
std::atomic<uint32_t> g_seq{0};          // par = estable, impar = escribiendo

// ESCRITOR (taskControl): nunca bloquea
void publicarEstado() {
  EstadoPlanta s = construirSnapshot();  // copia local coherente
  uint32_t seq = g_seq.load();
  g_seq.store(seq + 1);                  // impar
  g_estado = s;                          // struct POD ~100 B
  g_seq.store(seq + 2);                  // par
}

// LECTOR (web): reintento si pilló escritura a mitad
EstadoPlanta leerEstado() {
  EstadoPlanta local; uint32_t s1, s2;
  do {
    s1 = g_seq.load();
    local = g_estado;
    s2 = g_seq.load();
  } while (s1 != s2 || (s1 & 1));
  return local;
}
Un mutex FreeRTOS corto (~1 µs de memcpy) también funcionaría y es defendible — pero el seqlock elimina la categoría de problema entera, y para la tesis la frase "el lazo de control nunca es bloqueable por el consumidor de telemetría" es oro en defensa.

📡 C. ADS1115: single-ended, y una decisión de compra crítica
Differential vs single-ended: la respuesta es estructural, no de preferencia
Los pares diferenciales del ADS1115 son fijos: {AIN0−AIN1} y {AIN2−AIN3}. Necesitás ΔP_in = P1−P3 y ΔP_out = P2−P3 → P3 tendría que ocupar dos canales simultáneamente: imposible con un solo ADS1115 (requeriría dos chips). Pero además, single-ended es mejor acá por tres razones:

Diagnóstico: P3 negativo (succión) o P1 caído son alarmas distintas que el valor diferencial borra. El enclavamiento necesita TMP; la salud de la planta necesita cada manométrica.
Ruido: promediar 8-16 lecturas digitales por canal y restar en software es más limpio que confiar en el CMRR analógico con sensores de 0.5–4.5V ratiométricos (su error dominante es el propio sensor, no el ADC).
Flexibilidad: AIN3 queda libre para la TDS.

Protocolo de lavado entre corridas (criterio cuantitativo de aceptación)
Enjuague hidráulico: 10 min agua destilada a Q máx, retentado abierto, permeado a drenaje
Retro-lavado suave: 100–200 mL de agua destilada en sentido inverso (gravedad o UIF leve) — desmonta la torta laxa
Verificación Rm: 2-3 puntos agua limpia → criterio: Rm_post ≤ 1.05 × Rm_0. Si falla →
Limpieza química (el mucílago es polisacárido → NaOCl funciona sobre polisulfona): NaOCl 300–500 ppm, 20-30 min a ambiente → enjuague → (si hay incrustación) ácido cítrico 0.5%, 15 min → enjuague a pH neutro → re-verificar con criterio más estricto (≤1.02×Rm_0)
Bitácora: Rm vs nº de corrida (el envejecimiento es covariable), T° de cada ensayo (TCF), y jamás cambiar calibración de sensores a mitad de campaña
Presupuesto total: ~25-30 corridas de ~45 min = 3-4 jornadas de laboratorio. Realista para la tesis, y con las replicas del punto central tiene potencia estadística para el ANOVA.
